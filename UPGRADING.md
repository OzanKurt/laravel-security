# Upgrading

## From 0.x to 1.0.0-beta.1

This is a **breaking** release, all tables, config keys, and namespaces change. There is no automated migration; perform a fresh install.

### Steps

1. **Update composer.json**, change requirement from `ozankurt/laravel-security` to `ozankurt/laravel-shield`. The new package's `replace` clause handles the conflict:

   ```bash
   composer require ozankurt/laravel-shield:^1.0.0-beta
   composer remove ozankurt/laravel-security
   ```

2. **Drop the old tables** (if you ran 0.x in production):

   ```sql
   DROP TABLE security_logs;
   DROP TABLE security_ips;
   DROP TABLE security_auth_logs;
   ```

   Or run a manual `db:wipe` followed by `migrate` if your app uses only this package's tables.

3. **Run the install command:**

   ```bash
   php artisan shield:install
   ```

   This publishes config + migrations + lang + assets, runs migrations, generates `LS_AUDIT_HMAC_SECRET` + `LS_BYPASS_KEY` env values, seeds lookup tables and builtin WAF rules, and optionally adds your current IP to the bypass list.

4. **Update application code:**

   - Replace `OzanKurt\Security\*` namespace imports with `OzanKurt\Shield\*`
   - Replace `config('security.*')` calls with `config('shield.*')`
   - Replace `route('security.*')` calls with `route('shield.*')`
   - Replace `view('security::*')` / `@lang('security::*')` / `__('security::*')` / `trans('security::*')` with `shield::` namespace
   - If you had a custom gate definition, rename `viewSecurityDashboard` → `viewShieldDashboard`

5. **Update env file:**

   - Old `FIREWALL_*` env vars no longer used; replace with `LS_*` equivalents (see `config/shield.php` for defaults)
   - Required new env vars: `LS_AUDIT_HMAC_SECRET` (generated by `shield:install`), `LS_BYPASS_KEY` (generated by `shield:install`)
   - Optional: `LS_BYPASS_IPS` (comma-separated CIDR list of always-allowed IPs)

6. **Restart queues + caches:**

   ```bash
   php artisan optimize:clear
   php artisan queue:restart
   ```
